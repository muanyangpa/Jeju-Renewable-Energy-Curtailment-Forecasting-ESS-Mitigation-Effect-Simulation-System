# 기능 범위 확정 (작품소개서 4.3 / 5.1)

> **확정 원칙** — 최종심사 완성도 30점 S 기준이 *"작품소개서에 기술한 기능이 **모두** 완벽하게
> 작동함"*이다. **쓴 것은 전부 시연되어야 하므로, 시연할 수 없는 것은 쓰지 않는다.**
> 반대로 시연 가능한데 안 쓰면 점수를 버린다. 아래는 그 경계를 확정한 것이다.

## 2. 기능 범위 — 4단 분류

### 🟢 A. 지금 시연 가능 (작품소개서에 확정 기술)

| 기능 | 시연 방법 | 검증 상태 |
|---|---|---|
| **A1. 시간별 잉여 위험도 예측** | `POST /predict` — 24시간 확률·발전량 반환 | AUC 0.988(구 제도) / 0.9195(신제도 대리 라벨) |
| **A2. 발전원별 모델 자동 선택** | 수요예측 유무에 따라 4개 모델 중 자동 전환, `model_used`로 확인 | smoke_test 검증 |
| **A3. 입력 검증·에러 계약** | 23개·중복 → `INVALID_HOUR_SET`, 풍속 누락 → `MISSING_REQUIRED_FIELD` | smoke_test 4종 검증 |
| **A4. ESS 흡수율 시뮬레이션** | `POST /ess/simulate` — 실측 제어량 기반 흡수율 | 07장 문서값 재현(36.8%/48.4%) |
| **A5. ESS 용량 슬라이더** | `rated_power_mw`를 바꿔 반복 호출 | 22.5/30/40MW 검증 |

### 🟡 B. 11/11까지 구현 (작품소개서에 "구현 중"으로 기술)

| 기능 | 작업량 | 우선순위 |
|---|---|---|
| **B1. 대시보드 — 24시간 잉여 위험도 (등급 표시)** | 2~3일 | **최우선** |
| **B2. 대시보드 — ESS 용량 슬라이더 연동** | 1~2일 | 높음 |
| **B3. Backend 기동 + AI 서버 연동 데모** | 1~2일 | 높음 |
| **B4. 대시보드 — 검증 리포트 뷰** | 2일 | 중간 |

**B1이 가장 중요하다.** 심사위원이 보는 것은 API 응답 JSON이 아니라 화면이다. 전달력 10점과
완성도 30점이 여기 걸린다. 확률을 **등급(높음·보통·낮음)**으로 표시하는 것도 B1에서 구현한다 —
절대 확률을 노출하지 않는 것이 이 프로젝트의 원칙이다.

**B3는 선택 여지가 있다.** PostgreSQL 없이 시연하려면 DB 의존 기능(예측 이력 조회)을 빼고
프록시 기능만 보이면 된다. DB를 세우면 이력 조회까지 시연 가능하지만 리스크가 늘어난다.

### 🔵 C. 검증 자산 — 기능이 아니라 "근거"로 기술

작품소개서 3장(독창성)·5.2(리스크)에 넣되, **기능 목록에는 넣지 않는다.** 시연 대상이 아니다.

- 제도 전환 발견과 1차 자료 확증 (SFOC 보고서가 독립적으로 뒷받침)
- 라벨 구성 오류 수정 (테스트 64일 → 8,760시간)
- 설비 증설 착시 규명 및 정규화 (태양광 PR-AUC 0.406 → 0.711)
- 하루전 SMP 대리 라벨로 신제도 측정 (AUC 0.9195)
- 데이터 파이프라인 교차 검증 (비공개 원자료와 최대 4MWh 차이)
- 분포 적분 ESS 분석 (연구 검증 단계)

## 5. 대시보드 기술 선택

| 안 | 장점 | 단점 | 판단 |
|---|---|---|---|
| **Streamlit** | 계획서 기재와 일치, Python만으로 2~3일 | 실서비스 느낌 약함 | **권장** |
| React/Vue | 완성도 인상 좋음 | 프론트 공수 큼, 47일 내 리스크 | 비권장 |
| FastAPI + 정적 HTML | 서버 하나로 단순 | 차트 구현 직접 필요 | 차선 |

**Streamlit을 권장한다.** 계획서에 이미 기재돼 있고, 2인 팀이 Python으로 함께 작업할 수 있으며,
차트·슬라이더가 기본 제공된다. 완성도 30점은 "구현 수준"과 "기능 작동"을 보므로,
화려함보다 **기술한 기능이 전부 작동하는 것**이 중요하다.
